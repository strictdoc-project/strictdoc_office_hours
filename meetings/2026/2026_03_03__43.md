## Topic 1

I am trying to create an .sgra for a SEBoK Stakeholder role, which needs to
capture the following content per instance:

- Name Definition/Description (which may refer to a separate specification)
- Set of Authorizations (each of which should be reused from a single source of
  truth)
- Set of Qualifications (each of which should be reused from a single source of
  truth)

Each Set of _ field seem like a Node filled with only RELATIONS to a specific
TAG value, and different TAG values are used for an AUTHORIZATION vs a
QUALIFICATION. What should the stakeholder.sgra look like to express this
structure? How are the Set of _ "fields" supposed to be automatically validated?

**[STAKEHOLDER] NAME**: Installer **DEFINITION**: Third-party contracted
technical expert that is authorized to troubleshoot system issues and
immediately access the second-level support of the product. **AUTHORIZATIONS**:
Access account to product manufacturer's technical documentations, Ability to
change the password on the product. **QUALIFICATIONS**: At least 18 years old,
Tech training on the product [**STAKEHOLDER**] **NAME**: Operator
**DEFINITION**: Consumer that has purchased and is using the device at their
home. **AUTHORIZATIONS**: Ability to change the password on the product.
**QUALIFICATIONS**: At least 18 years old. [**SYSTEM_REQUIREMENT**]
**STATEMENT**: The system shall validate that the user indicates that they are
18 years ago. **RELATIONS**: **TYPE**: Parent **VALUE**: Qualification(18 years
old). **TYPE**: Parent **VALUE**: Security requirement (check for liability
reasons)
