## Removal of the Standalone Document export feature

1) Removal of the Standalone Document export feature where an HTML Document screen is exported with all images and JS/CSS embedded into HTML directly via Base64. This feature is seen to be of low value but adds code maintenance overhead. I am planning to remove it very soon, but want to check if there would be at least one vote for keeping it.

## Modeling Relations with Markdown

2) Tobias and I are discussing a format for modeling Relations with Markdown. My candidate is Proposal 4A, Tobias proposed 6, and last week we agreed that the 4A/4B is the one we choose for now. [https://gist.github.com/stanislaw/04b64b50a4429acb22c4cea64134f948](https://gist.github.com/stanislaw/04b64b50a4429acb22c4cea64134f948) Note that we are also experimenting with a similar format for RST. RST has a slightly different parsing mechanism but the outcome will be that both syntaxes look identical when seen in HTML or Markdown/RST browsers. The current winning option is therefore Proposal 3. [https://gist.github.com/stanislaw/264328b774dad28506bdcb81d475093c](https://gist.github.com/stanislaw/264328b774dad28506bdcb81d475093c). We encourage you to join the discussion and contribute your thoughts. I am also considering which format aspects are needed from this new Markdown format for modeling SPDX/RDF.

3) We could discuss which format can be used for constraining schemas of requirements documents written in Markdown or RST. Solving this can be also relevant for all other formats.
