## Topic 1

1. Release 0.25.0 with a few improvements, including more Markdown work and the
   new editable TABLE screen. More testing is needed - both features are
   experimental and are likely hiding corner cases that have not been uncovered
   yet. https://github.com/strictdoc-project/strictdoc/releases/tag/0.25.0

## Topic 2

2. We could discuss the non-native Markdown features that we need to implement
   and the question of which syntax to use for them: a) [LINK: ...] and [ANCHOR:
   ...] are already implemented, but are there any suggestions for something
   that would feel more Markdown-native? b) Do we want to implement
   [DOCUMENT_FROM_FILE] functionality in Markdown for including documents into
   each other? If so, which syntax should we use? c) Which syntax should we use
   for embedding source files into Markdown? Something like [SNIPPET_FROM_FILE:
   "foo/bar.py" lines=[123, 22] ]? d) Which syntax to use for external URL
   links? This needs to be implemented in both SDoc and Markdown and we
   postponed the implementation for way too long.

## Topic 3

3. We could discuss how to display documents with 10,000 requirements (asked by
   Luis last week). The only feasible approach seems to be enabling incremental
   viewing and editing in the web interface.

## Topic 4

4. We have thoughts on how to implement committing to Git via the editable UI
   interface. The spoiler is that we could leverage the existing Diff/Changelog
   engine for resolving Git conflicts should they arise, always preferring the
   main branch (prefer rebase, not merge).
